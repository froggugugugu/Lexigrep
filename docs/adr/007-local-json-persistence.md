# ADR-007: 手元で使い続けるための local モード(JSON 保存)

- ステータス: Accepted(オーナーが推奨案を承認)
- 日付: 2026-11-03
- 関連: `src/infrastructure/local/`、`src/infrastructure/repositories/data-source.ts`、ADR-001

## 背景

clone して自分の題材で学ぶ人には、Supabase を用意せずに学習記録を残せる手段が要る。memory モード(ADR-001)はプロセス内のストアで、再起動すると消える。

## 決定

- `LEXIGREP_DATA_SOURCE=local` を追加する。題材とカードは memory と同じく `content/` から読み、学習データ(SRS 状態・ログ・設定・間違い報告)だけを `.lexigrep/learning.json`(`LEXIGREP_LOCAL_DATA` で変更可、gitignore)に保存する
- 実装は memory の学習リポジトリを包み、書き込みのたびにファイル全体を保存する(一時ファイル → rename、プロセス内で直列化)
- 読めない / 形式が不正なファイルは上書きせずにエラーで止める
- 認証は memory と同じデモユーザー。本番ビルドでは memory と同じく既定で拒否する(`LEXIGREP_ALLOW_MEMORY=1` で許可)

## 代替案

| 案                                     | 長所                      | 短所(不採用の理由)                                                     |
| -------------------------------------- | ------------------------- | ---------------------------------------------------------------------- |
| PGlite のファイル保存 + SQL リポジトリ | Postgres と挙動が一致する | 3 つ目のリポジトリ実装と WASM の同梱設定が要る。1 人分のデータには過剰 |
| Supabase CLI のローカルスタック        | 本番と同じ                | Docker が要り、clone してすぐ動かない                                  |

## 影響

- 1 プロセス専用。同じファイルを 2 つのサーバーで使うと、後から保存した側で上書きされる
- 保存ファイルは学習データのスキーマで厳格に検証するので、スキーマに項目を足すときは optional + 既定値にする
- 「認証・DB は Supabase 一本」という当初の決定は本番の方針で、本決定はそれを変えない
